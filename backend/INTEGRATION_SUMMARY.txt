================================
DATA FLOW
================================

Voice Recording Flow:
  1. User clicks "Start Recording"
  2. Browser requests microphone permission
  3. MediaRecorder captures audio chunks
  4. User clicks "Stop Recording"
  5. Audio chunks combined into Blob
  6. Blob sent to backend via FormData
  7. Backend validates audio (size, format)
  8. Backend sends to Groq Whisper API
  9. Groq returns transcription text
  10. Backend returns JSON to frontend
  11. Frontend displays transcript in blue box
  12. User reviews and edits if needed
  13. User clicks "Confirm Transcript"
  14. Transcript populates textarea
  15. User proceeds with interview

Existing Typed Flow (Unchanged):
  1. User types answer in textarea
  2. User clicks "Next" or "Submit"
  3. Answer sent to backend
  4. Backend evaluates with MiniLM
  5. Score calculated and returned

================================
API SPECIFICATION
================================

Endpoint: POST /transcribe-audio

Request:
  Content-Type: multipart/form-data
  Body:
    audio: File (webm, wav, mp3, m4a, ogg, flac)

Response Success:
  {
    "success": true,
    "text": "transcribed text",
    "language": "en"
  }

Response Error:
  {
    "success": false,
    "error": "error message"
  }

Error Cases Handled:
  - No audio file provided
  - Empty/silent recording
  - File too large (>25MB)
  - File too small (<1KB)
  - Unsupported format
  - Groq authentication failure
  - Rate limit exceeded
  - Network timeout
  - Empty transcription result
  - Corrupted audio file

ERROR HANDLING STRATEGY
================================

Frontend Errors:
  - Microphone permission denied → Clear message + instructions
  - No microphone found → Hardware check message
  - Recording too short → Retry prompt
  - Network error → Connection check message
  - Transcription failed → Retry option

Backend Errors:
  - Invalid file → Format specification
  - File too large → Size limit message
  - API authentication → Key validation
  - Rate limit → Retry later message
  - Timeout → Try again message

All errors:
  - User-friendly messages
  - No technical jargon
  - Actionable instructions
  - Retry options provided
